Брошенных замков не было.

Важно для чисел ниже: всю ночь машина работала в подкачке (занято 4-11 ГБ из

Время счёта клона из-за этого гуляет: одна и та же фраза - 12-28 с. Поэтому

## Итог в двух словах

- Звук по мере готовности сделан одним модулем (`core/stream.py`) для окна,
  консоли и сервиса `/speak`. Звук потока совпадает с итоговым файлом до
  сэмпла; пробник по-прежнему ложится файлом рядом с книгой.
- **Быстрый голос (Silero) и `/speak`** - цели выполнены с запасом: первый
  звук через 0,13-0,15 с.
- **Клон F5 - цели «≤ 3 с» и «пробник вдвое раньше» не достигнуты.** Причина
  в самой модели: каждый вызов F5 стоит не меньше 5-6 с на M4 (прогон образца
  голоса), а с проверкой слов пробник считается в 2-2,4 раза дольше своего
  звука. Звук начинается раньше, чем раньше, но без запинок раньше начать
  нельзя - числа ниже.

## П. 6. Время первого звука (Mac, модель загружена)

| что | цель | факт | запинки |
|---|---|---|---|
| «Быстрый» голос Silero, фраза 5 с | ≤ 0,7 с | **0,13-0,15 с** (сразу после загрузки - 0,5 с) | нет |
| `/speak` из другой программы, Silero | ≤ 1 с | **0,05 с**; первый запрос после включения сервиса - 0,94 с | нет |
| клон F5, фраза ~11 с, 12 шагов | ≤ 3 с | **12,2-12,3 с**; 27,8 с, если кусок пересчитан из-за краёв | нет |
| клон F5, та же фраза, 8 шагов (живой профиль) | ≤ 3 с | **7,5 с**; 15,8-18,4 с при пересчёте | нет |
| клон F5, пробник 1 мин, как в книге (с проверкой слов) | вдвое раньше, чем весь пробник (126 с → ≤ 63 с), без запинок | **97-103 с** (весь счёт 110-113 с) | нет |
| клон F5, пробник 1 мин без проверки слов | для сравнения | **37,3-37,8 с** (весь счёт 71 с) | нет |

Пробник без проверки слов почти на пределе: по ходу прогона (когда вышел
каждый кусок) без запинки раньше 35 с начать было нельзя. С проверкой предел -
около 75 с: второй кусок проверка пересчитала и прочитала по предложениям
(51 с вместо 20), а заранее это не предсказать, поэтому расчёт держит запас.

Почему клон не успевает:

| кусок (12 шагов) | звука | чистый счёт F5 |
|---|---|---|
| 21 знак | 1,9 с | 6,2 с |
| 53 знака (одно предложение) | 4,7 с | 7,4 с |
| 187 знаков (полный кусок) | 13,4 с | 14,1 с |
| 21 знак, 8 шагов | 2,0 с | 3,6 с |
| 53 знака, 8 шагов | 4,6 с | 4,5 с |

Постоянная часть - около 5,3 с на вызов при 12 шагах и около 3 с при 8: модель
каждый раз заново прогоняет образец голоса (~10 с звука). Даже самый короткий
кусок не даст звука раньше 6 с (12 шагов) или 3,6 с (8 шагов). Модель по
заданию не меняли.

Отсюда же решение про первый кусок. Короткий первый кусок помогает, только
когда движок быстрее реального времени (Silero). У клона лишний вызов
прибавляет те же 5 с и отодвигает момент, когда можно играть без запинок.
Поэтому модуль сам считает оба варианта по замеренной скорости голоса и
берёт тот, где звук начнётся раньше: Silero режется, клон обычно нет.

Пробник с проверкой слов: 54 с звука считаются 110-130 с (часть кусков
проверка пересчитывает, один - до 53 с). Начать без запинок можно не раньше,
чем «счёт минус звук», то есть около 60-75 с, и то при точном знании, какой
кусок будет пересчитан. Заранее этого не знает никто, поэтому расчёт честно
ждёт: 97-103 с против прежних 126.

## Что сделано (пп. 1-5)

**1. Общий механизм** - `core/stream.py`:
- текст режется как в книге (`_chunk_paragraphs`); короткий первый кусок
  (одно предложение 40-100 знаков) - когда это даёт звук раньше (см. выше);
- куски считает обычный `_synth_chunks` - те же ударения, числа, паузы,
  поправки голоса (темп, высота, бас, яркость), проверки и кэш. Склейка
  пошаговая, тем же кодом, что файл (`_Joiner`), поэтому поток = файл до
  сэмпла (проверено на заглушке при RTF 0,1 / 1,0 / 1,8);
- кусок играет, только когда посчитан целиком: если машина не успела, пауза
  выходит на стыке предложений, а не посреди слова;
- полировка звука и поправки голоса - ffmpeg на каждый кусок (на стыках
  тишина, фильтрам не на чем щёлкнуть). Разница с полировкой целого файла -
  на 167 дБ тише звука, т. е. её нет;
- звук через sounddevice (PortAudio) на всех трёх системах: AVAudioPlayer на
  Mac потоком играть не умеет. Мини-плеер готовых частей - прежний. Нет
  звуковой карты - звук играется файлом по готовности, как раньше;
- «Пауза» держит звук (счёт идёт дальше, запас копится), «Стоп» обрывает звук
  сразу и синтез - на ближайшем стыке (следующий кусок уже не заказывается).

**2. Когда начинать.** Старт - когда каждый следующий кусок успеет
досчитаться (+10 %) раньше, чем до него дойдёт игра. Скорость - по замерам
этого движка и голоса, запоминается между запусками
(`~/.cache/text2audio/live_speed.json`): время куска = постоянная часть +
доля от длины звука, с поправкой на то, что упреждение считает следующий
кусок, пока проверяется текущий. Окно пишет «Звук начнётся через ~N с» с
обратным отсчётом, потом «Играет · считаю дальше». Проверка слов по звуку:
в пробнике - как в книге; в «Прочитать вслух», «Прослушать», «Послушать» и
`/speak` - выключена. Звук потока уже проверен (кусок уходит в игру после
проверки), поэтому «заменённый, но уже прозвучавший» кусок не возникает.

**3. Где включено:** пробник; «Прослушать» в «Голосах» (сырой звук фразы
запоминается: новые ползунки, кроме темпа, звучат мгновенно); Настройки -
у каждого движка кнопка «Послушать» (фраза выбранным клоном этим движком).

**4. «Прочитать вслух»** - карточка на главной: поле, «Из буфера», «Быстрый /
Клон» (по умолчанию быстрый), «Прочитать» (во время чтения - «Стоп»),
«Сохранить» (mp3 после прослушивания). Язык - тем же определением, что у
книги; английский быстрым голосом не читается (готовых английских голосов
нет) - тогда читает клон, окно об этом пишет. Пока озвучивается книга, все
кнопки прослушивания заперты.

**5. Для других программ:** `cli.py --speak "текст"` (или `-` из stdin,
`--fast`, `--save файл.mp3`), `cli.py --serve`; в окне - Настройки →
«Озвучка для других программ» (выключено, порт 8716, выгрузка моделей после
5-60 минут простоя). `POST /speak` отдаёт WAV потоком, начало ответа
придержано по тому же расчёту - если играть сразу, как приходит, звук не
запнётся; `"play": true` - Herald играет сам. Только 127.0.0.1: чужой Host
и чужие сайты получают 403 (проверено в test_gui). Примеры на Python и JS -
в README.

## П. 7. Замечания по слуху («Сравнение 3.3 - глава»)

**«лОгично».** Текст верный: «Лог+ично» стоит одинаково в начале предложения,
после тире, со строчной и даже капслоком. Общей причины в расстановке нет:
в книге (первые 120 тыс. знаков) у 294 слов, что встречаются и первыми в
предложении, и в середине, ударение различается только у двух - и оба
омографы, решённые по смыслу («какая», «связи»). Значит, модель не
послушалась верного знака - то же, что «скользя / выхватил» в 3.2. Тот же
кусок с тем же зерном без проверки (187 знаков) прочитан верно, т. е. дело
не в длине куска, а в случайности конкретного дубля.

Проверил две общие гипотезы:
- текст образца без «+» (а куска - с «+») сбивает модель на первых словах.
  Опыт: первые три куска главы, 6 зёрен, образец с разметкой ударений и без
  (длительности одинаковые). Ударения совпали с «+» в 67 % и 68 % слов -
  разницы нет, гипотеза отвергнута;
- ловить ошибку по звуку (ударная гласная длиннее и громче). На «Логично»
  это работает (в варианте Л сильнее всех звучит первая «о», доля ударной
  0,17, в остальных вариантах 0,29-1,0), но на всей главе совпадение с «+»
  лишь 47 % - каждое восьмое верное слово было бы признано ошибкой. В
  проверку такой признак ставить нельзя.

Итог: общего механизма, который ловит или предотвращает такую ошибку, не
нашёл; словарей под слова не делал.

**«никогооо».** Это не конец куска: «…нет никого, кто располагался…» - в
середине первого куска, перед запятой. Замерил, сколько голос тянется после
конца слова (по выравниванию), на той же главе в четырёх вариантах:

| вариант | обычно (медиана) | 99-й процентиль | «никого» |
|---|---|---|---|
| 3.2 (Е) | 0,08 с | 0,36 с | 0,12 с |
| 3.3 (Л) | 0,08 с | 0,34 с | 0,28 с |
| 187 без проверки | 0,08 с | 0,40 с | 0,20 с |
| 3.2, другое зерно | 0,08 с | 0,41 с | 0,10 с |

На концах кусков хвост одинаковый в 3.2 и 3.3 (медиана 0,18-0,21 с,
наибольший 0,35-0,45 с): короткие куски растяжений не умножили, частого
растяжения нет. «Никого» в Л тянется вдвое дольше, чем в других вариантах,
но для этого голоса это ещё норма (0,28 с при 99-м процентиле 0,34-0,41) -
порог, который поймал бы его, задевал бы каждое двадцатое слово.

Сделано общее: проверка слов по звуку теперь пересчитывает кусок, если голос
тянется после слова дольше 0,6 с (выше всей нормы голоса; на четырёх главах -
2 слова из ~1200: «аборигена» 0,98 с, «наплевать!» 0,81 с), а из дублей
берётся тот, где растяжений нет. «Никого» 0,28 с этим не поймать - честно.

«Слова» 3.3: ошибки в обоих вариантах, вы выбрали 3.2. Дальше - живой текст
(`Примеры текстов/Живая проверка/`), файл «Что слушать» я не открывал.

## Известные ограничения

- Клон F5 не даёт первого звука раньше 6 с (12 шагов) / 3,6 с (8 шагов) на
  M4 - это стоимость одного вызова модели.
- Пробник с проверкой слов почти не стал раньше (97-103 с против 126):
  пересчёты непредсказуемы. Если важнее быстрый первый звук - проверку для
  пробника можно выключить (звук через ~38 с), но это ваше решение: по
  заданию пробник проверяется как книга.
- «Стоп» обрывает звук сразу, а текущий кусок модель досчитывает (до 5-15 с) -
  прервать вызов MLX посреди нельзя; новый заказ ждёт его.
- Прогноз скорости учится на первых прогонах: самый первый прогон нового
  голоса может запнуться на стыке (прикидка без замеров).
- Английский текст быстрым голосом не читается - готовых английских голосов нет.
