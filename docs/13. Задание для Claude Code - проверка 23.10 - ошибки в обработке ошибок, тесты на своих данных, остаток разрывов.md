## А. Сообщения об ошибках сами падают (класс: замыкание на `e` после `except`)

Факт. `except Exception as e: self.ui(lambda: ... e ...)` - Python удаляет `e` при выходе из блока, лямбда выполняется позже в главном потоке и падает с `NameError`. Пользователь не видит причину, окно застревает. Пойман вживую: нечитаемая книга → навсегда «Считаю объём книги…».

Места (`ruff --select F821`): `tts_gui.py` 1541, 1650, 2293, 2474, 3239, 3359. Плюс `core/pipeline.py` B023 (замыкание на переменную цикла): 1062, 1083, 1091, 1825, 1827 - разобрать каждый.

Сделать:
1. Исправить все места одним способом: значение передаётся в лямбду явно (`msg = str(e); self.ui(lambda m=msg: ...)`) или через общую функцию `self.ui_error(where, e)`, которая и пишет в журнал, и показывает.
2. Стандарт 6.11: `ruff check --select F821,F841,B023` в тестах и CI, F821 = 0.
3. Тест: подсунуть нечитаемую книгу, «Проверить голос» с битым образцом, «Как будет прочитано» с ошибкой - в окне понятное сообщение, не зависание.
