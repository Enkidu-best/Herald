## Часть 1. Проверка по звуку

### Как устроена

Whisper больше не судит середину куска. Текст книги **укладывается на звук**
(forced alignment) акустической моделью без языковой догадки: wav2vec2 по
буквам, `bond005/wav2vec2-large-ru-golos` (Apache-2.0, локально, 1,3 ГБ,
качается один раз). Для каждой буквы видно, насколько звук на её месте похож
именно на неё; для слова - средняя такая вероятность и что модель слышит на его
месте сама (по буквам, без словаря).

Слово под подозрением, если:
- его буквы почти не слышны (средний логарифм вероятности < −3,5) - слово
  съедено или пропало;
- или вероятность заметно снижена (< −0,8) **и** модель слышит на его месте
  другие согласные (сходство согласного «скелета» < 0,6). Гласные не
  сравниваются: безударные русская речь редуцирует («абориген» → «обреген»),
  это не ошибка.

Это общее правило, без слов под конкретный текст. Сравнивались две модели:
`jonatasgrosman/wav2vec2-large-xlsr-53-russian` (Apache-2.0) ловит так же, но
чаще срабатывает зря и спотыкается на «ё». Взята golos.

**Лечение** - как в задании: подозрительный кусок пересчитывается с другим
зерном до 2 раз, берётся дубль с лучшим **худшим** словом. Добавлено одно:
если после пересчёта под подозрением **те же** слова, зерно уже не поможет -
кусок читается по предложениям и склеивается с обычными паузами. Нашлось на
главе: «Раз мы здесь» пропадало во всех дублях длинного куска.

### Поправка к прежней цифре

В черновом подсчёте у строгой 3.2 выходило 27 % ложных кусков. Это была ошибка
моей разметки: в «словах» текст отрывка стоял в эталоне целиком, а в записи
его нет - строгая проверка честно считала эти слова пропавшими. Без этих
кусков - 2 из 35 (6 %), как в таблице. То есть **строгая 3.2 срабатывает зря
реже, но и ловит меньше**; новая ловит больше ценой лишних пересчётов.

| зерно | куски | под подозрением | RTF |

| 33 | 280 знаков (было) | 4 слова: «Раз мы здесь» пропало | 1,50 |

## Часть 3. Что по умолчанию и время

| вариант (глава, зерно 33) | RTF | время к «без проверки 3.2» | подозрительных слов в итоге |
|---|---|---|---|
| 3.2: 280, без проверки | 1,50 | - | 4 |
| 280 + проверка по звуку, первая версия | 2,81 | +87 % | 5 |
| 280 + проверка + чтение по предложениям | 2,81 | +87 % | 0 |
| 187, без проверки | 1,52 | +1 % | 2 |
| **3.3: 187 + проверка по звуку** | **1,79** | **+19 %** (+17 % к 187 без проверки) | **0** |

Первая версия съедала время по двум причинам: выравнивание на процессоре
занимало все ядра и тормозило синтез на видеоядре (теперь ему 2 потока), и
стойкие пропуски пересчитывались впустую. «0 подозрительных» у вариантов с
проверкой - это оценка той же моделью, которая и отбирала дубли, поэтому
настоящий судья - ваш слух.

**Решение по правилу задания:** на наборе новая лучше старой (9 против 7 из 10),
прибавка времени 17-19 % ≤ 25 % → **проверка по звуку включена по умолчанию**
(Настройки → «Проверка слов по звуку»), **строгая 3.2 из окна убрана** (в коде
осталась для замеров). Прогноз «ждать около» с проверкой - ×1,2.

На диалоге («слова») проверка дороже: RTF 3,8 против 1,36 - кусков мало, и два
стойких места («что он вернётся», «и огляделся») пересчитываются во всех
дублях и при чтении по предложениям. Похоже, эти фразы модель с этим голосом
так и произносит - на слух в 3.2 это и было слышно. На книге такие места
редки, поэтому в среднем - те же +17-19 %.

Готовые голоса Silero по звуку не проверяются: слов не глотают, а выравнивание
шло бы дольше их собственного счёта. Английский - тоже нет (модель русская).

При первом запуске 3.3 модель проверки качается один раз (1,3 ГБ), окно пишет
«Скачиваю модель проверки слов…». Если модель недоступна - озвучка идёт
дальше без проверки, в журнале запись.
