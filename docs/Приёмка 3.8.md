# Приёмка Herald 3.8

По заданию `docs/10. Задание для Claude Code - Herald 3.8 (голоса в одном месте, наушники, упрямые ударения).md`
и `../Стандарт интерфейса программ.md`. Mac - Apple M4 16 ГБ. Работа с моделями -
под `../.heavy-lock`.

Итоги слепых наборов 3.7 приняты как в задании: части с омографами в полную
подсказку **не** переводятся (п. 4 задания 09 не делаю).

## Часть 2. Голоса - всё в разделе «Голоса»

- Скачивание, удаление и «Послушать» перенесены из «Настроек» на страницу
  «Голоса»; в «Настройках» карточки голосов больше нет.
- Один список, **каждый голос - строкой**: клоны, затем все готовые голоса
  (Silero, Vosk 4 / 3 / 2, Piper Joe / Kristin / Cori). В строке - пол, язык,
  движок, размер и состояние («встроен», «не скачан», «скрыт», «выбран для
  озвучки»); справа - «Послушать», «Скачать» (если не скачан), «⋯».
- Vosk: один файл модели на три голоса - в каждой строке «входит в пакет Vosk
  747 МБ». «Удалить…» у одного голоса Vosk его скрывает; когда скрыты все три,
  программа предлагает удалить сам пакет с диска.
- **«✎» у названия - своё имя голоса** (клоны и готовые): оно показывается во
  всех списках (озвучка, «Прочитать вслух», «Голоса»), исходное - мелко серым
  рядом; «Исходное имя» возвращает как было. Имя хранится в профиле
  пользователя (`herald.json`), а не в файле поправок голоса: иначе
  переименование сбрасывало бы «Продолжить» и кэш синтеза.
- Удаление и скрытие - в меню «⋯» строки, с подтверждением (стандарт, п. 3).
- Заодно: у быстрых голосов в имени «:» («vosk:4»), а файл поправок звучания
  `<голос>.fx.json` с «:» на Windows создать нельзя - теперь «:» → «_»,
  прежний файл читается.
- Проверка - `test_gui` («Голоса»: строка на голос, послушать, скачать, нет
  сети, «⋯» удалить, Vosk - скрыть по одному и удалить пакет, своё имя).

## Часть 3. «Прочитать вслух»

- **Одна кнопка ▶ / ❚❚**: «Прочитать» → «Пауза» → «Продолжить»; ■ -
  остановить. Пробел - то же самое, если курсор не в тексте (в тексте пробел
  остаётся пробелом).
- **Звук - на текущее устройство системы, на лету.** Причина «звук идёт не в
  наушники»: PortAudio запоминает список устройств при первом обращении и
  открывает поток на конкретном устройстве - наушники, подключённые после
  запуска, он не видел ни для идущего звука, ни для нового. Теперь на Mac
  устройство системы читается из CoreAudio каждые 0,5 с; сменилось - список
  устройств перечитывается, и поток переоткрывается на новом месте с той же
  точки (теряется один блок ~20 мс). Новый звук тоже идёт на текущее
  устройство.
- Настройки → «Устройство вывода»: «Как в системе» (по умолчанию) или
  конкретное устройство по имени.
- Проверено на Mac (`scenario_audio_out.py`): наушников у этого Mac под рукой
  нет, а «Microsoft Teams Audio» система устройством вывода сделать не даёт.
  Поэтому сценарий создаёт временное составное устройство поверх динамиков
  (его система принимает как устройство вывода, звук остаётся в динамиках),
  во время звука делает его устройством системы и обратно, а потом удаляет.
  Итог: звук перешёл на новое устройство и вернулся, доиграл до конца
  (6,0 с из 6,0). Контроль: с выбранным в Настройках конкретным устройством
  звук остаётся на месте - то есть проверка различает.
- **Не проверено вживую:** настоящие проводные и Bluetooth-наушники (нужны
  ваши руки) и Windows. На Windows PortAudio по умолчанию выводит через
  «Microsoft Sound Mapper» - его Windows переводит на новое устройство сама;
  на Linux поток переносят PulseAudio / PipeWire.

## Часть 4. Прогноз с готовыми кусками

- «Проба пера 3» второй раз: прогноз 2:19, факт 0:55 - куски брались из кэша
  синтеза, а прогноз этого не знал (он не прогоняет всю книгу через RUAccent,
  а ключ кэша - от текста с ударениями).
- Теперь озвучка кладёт в `<книга>/_служебное/куски.json` список кусков ровно
  как они уходят в модель (текст и темп) - сразу, в начале, так что он есть и
  после «Остановить». Прогноз в фоне пересчитывает ключи кэша **при текущих
  настройках** (движок, режим, голос, его темп) и смотрит, какие куски уже
  посчитаны: «Ждать около 0:50» и строка «12 из 15 кусков уже посчитаны - они
  возьмутся из готового». Другой голос или режим честно дают «ничего не
  готово»; файл книги поменялся - список не используется.
- Замеры: скорость частей и раньше считалась только по новому звуку, а вот
  «ожидание книги целиком» записывалось вместе с кусками из кэша - отсюда и
  заниженный прогноз в следующий раз. Теперь оно считается на секунду нового
  звука; если нового меньше 20 с - не записывается вовсе.
- Проверка - `test_forecast_cache.py` (три четверти кусков в кэше, другой
  голос, изменённая книга) и `test_gui` («12 из 15 кусков уже посчитаны»,
  ждать меньше).
