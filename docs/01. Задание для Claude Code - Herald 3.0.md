# Задание для Claude Code - Herald 3.0

Основа - ревизия дизайн-чатом 14.10 (README, core/, tts_gui.py, «Инструменты разработки», Консультации) и замечания Андрея после озвучки книги «Жажда власти»:
1. ударения неверны примерно в 1-15 % случаев;
2. качество голоса «3+ / 4-»: железный отзвук, речь не совсем естественная;
3. окно должно выглядеть как Legal Knowledge Desk и Scribe 2.2.

**Правила:**
- решения только общие: никаких ручных словарей ударений и правил под конкретную книгу или голос;
- «числа расходились с ухом трижды» (ЭТАЛОННЫЕ_НАСТРОЙКИ.md): **голос выбирает Андрей на слух, вслепую**, метрики только отсекают явный брак;
- основной движок не менять, пока Андрей не выбрал в слепом прослушивании (раздел 2);
- новые пакеты - только в `.venv` проекта, глобальный torch (Scribe, Anonymizer) не трогать;
- каждое изменение проверять реальным прогоном через окно;
- в конце: коммит, HANDOFF.md, README, версия **3.0**.

Работа идёт в два этапа:
- **Этап 1** (разделы 1-3) - делать сразу;
- **Этап 2** (раздел 4) - после того, как Андрей прослушает набор из раздела 2 и назовёт победителя.

## 1. Ударения

Сейчас: RUAccent (turbo3.1 + словарь) ставит «+» на весь текст главы, F5 accent_tune озвучивает.

Ошибка может возникать в двух местах, и лечатся они по-разному:
- **(а) неверный «+» в тексте** - ошибся расстановщик;
- **(б) «+» верный, но модель его не послушалась.**

1.1. **Разделить ошибки (а) и (б)** на книге Андрея (`Книги/Жажда власти 1 - Сергей Тармашев`).
- Взять 2-3 главы, сохранить текст с ударениями.
- Отдельно посчитать: сколько слов вне словаря (имена, выдуманные слова фантастики). Там расстановщик угадывает, и там вероятнее всего большая часть ошибок.

1.2. **Сравнить расстановщики на открытых размеченных наборах** (не на ручной разметке):
- RUAccent turbo3.1 (сейчас);
- **silero-stress 1.5** (`pip install silero-stress`, MIT, сентябрь 2026). По замеру авторов на омографах: точность по словам 0,92 против 0,76 у RUAccent turbo3.1; словарь 4,1 млн форм; ставит «ё»; работает в один поток CPU.

Наборы: открытые тестовые наборы омографов и ударений (из статей RUAccent и silero-stress на Хабре и в репозиториях), плюс словарные формы.

Дополнительно на книге Андрея - список слов, где два расстановщика расходятся, с количеством. Если расходится мало мест, этот список уйдёт Андрею в слепую проверку (п. 2.4).

Выбрать лучший по замеру. Если победил silero-stress, перевести его вывод в формат «+», который понимает F5. Оставить запасной путь на RUAccent.

1.3. **Единообразие внутри книги.** Слово вне словаря (имя героя, название) должно звучать одинаково во всей книге. Сейчас расстановщик может поставить разное ударение в разных главах.

Общее правило:
- для слов вне словаря собрать все варианты по книге и выбрать один - самый частый или самый уверенный;
- применять его везде;
- омографы словаря (зáмок/замóк) не трогать, их решает контекст.

1.4. **Проверить (б): слушается ли модель «+».**
- 30 коротких фраз с известным ударением, включая пары омографов («Он открыл з+амок» / «Ключ от зам+ка»).
- Синтез на текущем движке и на каждом кандидате раздела 2.
- Фразы входят в слепой набор (п. 2.4).
- Если модель часто игнорирует «+» - это довод против неё при выборе в разделе 2.

1.5. **Ё.** Проверить, что «всё / все», «её», «ещё» доходят до синтеза с «ё». Нормализатор ничего не должен терять.

## 2. Качество голоса - сравнение вслепую

**Что выяснено при ревизии:**
- По умолчанию синтез идёт за **7 шагов** (EPSS). Его выбрали по разборчивости ASR (94,1 % против 94,5 %). Разборчивость - не естественность: малое число шагов в F5 даёт как раз «металл» и ровную интонацию. У F5 по умолчанию 32 шага, у ESpeech - 48. Сравнение 7 / 16 / 32 на слух вслепую не делалось.
- Русская модель - Misha24-10 F5 accent_tune с вокодером Vocos 24 кГц. В «Консультациях» он уже записан как потолок по «металлу» для ярких голосов.
- С тех пор вышли модели, которые в обзорах русского TTS 2026 года оценены выше или на уровне:
  - **ESpeech-TTS-1** (RL-V2 и SFT, Apache-2.0) - та же архитектура F5, обучена на русском, тоже понимает «+». Встаёт в наш движок f5_mlx сменой чекпойнта и словаря, без новой библиотеки;
  - **Qwen3-TTS 1.7B Base** (Apache-2.0, январь 2026) - русский среди 10 языков, клон по образцу от 3 с, другой принцип (языковая модель по аудиотокенам), есть порт на MLX (mlx-audio). Известные слабости: ударения ставит сама и иногда ошибается, на длинных текстах бывают сбои;
  - **Chatterbox Multilingual v3** (Resemble AI, MIT, июнь 2026) - русский, клон;
  - **Silero v5 ru** - готовые голоса, не клон, очень быстрый, ударения из silero-stress. Нужна как ориентир «чистого» звука. Лицензия только некоммерческая.

2.1. **Кандидаты** (голос-образец один для всех клонов - **Вячеслав Герасимов**, одобренный):

| Код | Что |
|---|---|
| A | сейчас: F5 Misha accent_tune, 7 шагов EPSS, текущая обработка |
| B | то же, 32 шага |
| C | ESpeech-TTS-1 RL-V2 в нашем f5_mlx, 32 шага (если RL-V2 недоступна - SFT) |
| D | Qwen3-TTS 1.7B Base, клон, MLX (mlx-audio) или torch MPS |
| E | Chatterbox Multilingual v3, клон |
| F | Silero v5 ru + silero-stress, лучший мужской голос (ориентир, не клон) |

Для B и C при хорошем результате добавить 16 шагов: возможно, середина по скорости.

Если кандидат не ставится в `.venv` или не помещается в 16 ГБ:
- записать причину;
- исключить;
- без недельных обходов.

Ограничение по времени на установку одного кандидата - разумное: если не заработал за пару часов, исключаем.

2.2. **Тексты** - одинаковые для всех, по 40-60 с звука:
1. повествование из книги Андрея;
2. диалог с эмоцией (вопрос, восклицание, реплики);
3. сложный: числа, даты, сокращения, имена, омографы.

Плюс 30 фраз из п. 1.4.

2.3. **Отсев перед прослушиванием** - только явный брак: выпавшие слова (ASR), треск, щелчки, обрывы краёв. Гейт `voice_report.py` - как справка в отчёте, не как решение.

2.4. **Слепой набор для Андрея** - папка `Сравнение голосов 3.0/`:
- файлы названы случайными буквами («Вариант К.mp3», «Вариант Р.mp3» …), одна и та же громкость (LUFS), одна и та же финальная обработка, формат mp3 192;
- ключ «буква → модель» - в `docs/ключ сравнения (не открывать до оценки).md`;
- лист оценки `Оценка.md`: для каждого варианта три оценки 1-5 (естественность, «металл / чистота», ударения) и поле для замечаний;
- для фраз п. 1.4 - список «фраза → какое слово прозвучало неверно»;
- рядом короткий отчёт: скорость каждого варианта («час звука за N мин»), память, лицензия, сложность установки.

На этом этап 1 по голосу останавливается: ждём оценки Андрея.

2.5. **Пост-обработка** (Resemble Enhance и подобные) - пока не делать. Сначала выбрать модель: хорошая модель лучше починенной плохой.

## 3. Ревизия кода - найдено, исправить

3.1. **Сон Mac посреди озвучки.** Книга считается 6,5 ч, а программа не запрещает системе засыпать. На время синтеза держать `caffeinate -i -w <pid>` (или IOPMAssertion), снимать по окончании и по «Стоп».

3.2. **Продолжение после сбоя.** Сейчас после закрытия окна или сбоя на 30-й части книгу приходится считать с нуля.
- Готовые части пропускать, если совпадают текст части, голос и настройки (хэш в файле рядом).
- Кнопка «Продолжить озвучку» при повторном открытии той же книги.

3.3. **Временные файлы не удаляются.** `pipeline.py` создаёт `t2a_syn_*` (`mkdtemp`) и нигде не удаляет. Там WAV глав: для 8-часовой книги это гигабайты на каждую озвучку. Нужно:
- удалять по окончании и по «Стоп»;
- при запуске чистить старые `t2a_*` старше суток.

3.4. **48 мест `except Exception`**, многие молча глотают ошибку (`except Exception: pass`, например загрузка настроек голоса).
- Пройти все.
- Где ошибка меняет результат - писать в лог `~/Library/Logs/Herald/herald.log` и показывать в окне.
- Тихо оставлять только то, что действительно не важно.

3.5. **Незакоммиченное.** `git status`: удалён файл в «Примеры текстов». Разобраться, закоммитить или вернуть.

3.6. **Лицензии** - записать в README:
- Misha24-10 / F5 - веса CC-BY-NC, только некоммерческое использование;
- для каждой новой модели раздела 2 - её лицензия.

Это важно, если Herald когда-то станет продуктом.

3.7. **Тире.** Длинное «—» → короткое « - » во всех строках окна, README, именах файлов.

## 4. Этап 2 - после выбора Андрея

4.1. **Сделать выбранную модель основной.**
- Остальные проверенные - в Настройках как «другие движки», если ставятся без проблем.
- Неудачные не тащить в код.
- Переозвучить пробник и главу книги для проверки Андреем.

4.2. **Окно в стиле LKD / Scribe 2.2.** Взять `theme.py` и иконки Lucide из Scribe (`../Аудио в Текст/theme.py`, `assets/icons/`):
- те же цвета, светлая и тёмная тема, системный шрифт, карточки с тонкой рамкой, цветные статусы;
- боковое меню: **Озвучка · Голоса · Настройки · Тема**.

Страница «Озвучка»:
- зона «Перетащите книгу», после выбора - карточка книги: название, автор, главы, «сколько звука / сколько ждать»;
- выбор голоса, длина частей, формат;
- «Проверить голос (1 мин)» и большая кнопка «Озвучить книгу», которая на время работы становится «Остановить», плюс «Пауза»;
- под шкалой этап словами: «Шаг 1 из 3 · Подготовка текста: числа и ударения» → «Шаг 2 из 3 · Озвучка - часть 4 из 27, 15 %» → «Шаг 3 из 3 · Сборка файлов»; общий процент и оставшееся время;
- список готовых частей с кнопками «Слушать» и «Показать в Finder».

Страница «Голоса»:
- список голосов (язык, образец);
- «Добавить образец…»;
- настройки тембра (сейчас кнопка ♪);
- прослушивание.

Технический лог - свёрнутый блок «Подробности» с кнопкой «Копировать».

Проверить светлую и тёмную тему, мерцаний при переключении страниц быть не должно (опыт Scribe 2.2: перекрашивать меню до показа страницы, страницы строить заранее).

4.3. **Подсказки и тексты** - простым языком, без технических слов в основном окне (RTF, EPSS, NFE - только в Настройках «для опытных»).
