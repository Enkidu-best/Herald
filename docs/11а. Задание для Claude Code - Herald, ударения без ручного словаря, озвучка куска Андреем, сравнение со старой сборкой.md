## Решение Андрея: ручного словаря не будет

Вопрос из отчёта («вернуть словарь?») закрыт - **нет**. Андрей узнаёт об ошибке только при прослушивании готовой книги; собирать слова по книге, вести словарь и переозвучивать - тупиковый путь. Ударения должны ставиться верно **автоматически**, как в современных системах.

Как это делают сейчас (проверить и дополнить своим поиском):
- Пользовательские словари в коммерческих TTS (Amazon Polly lexicons, Azure custom lexicon) - только для имён, брендов, сокращений; основное произношение ставит автоматика (G2P и разрешение омографов по контексту).
- RUAccent (COLING 2025): морфология + нейросети с контекстом + ё-фикатор, точность 0,96 на омографах и 0,97 на остальных - **при полном контексте предложения**.
- Автоматическая самопроверка синтеза распознаванием и пересинтез (Microsoft, «Automated TTS self correction system»; Interspeech 2005 «ASR-assisted pronunciation issue detection»). У нас пересчёт по meter2 не помог, потому что проверка сравнивает звук **с той же неверной разметкой** - нужна независимая оценка.

Что видно из нашего замера (пункт 1 задания 11): модель знаку ударения подчиняется; ошибки - в разметке («стены», «все/всё», «щавель», «красивее»). Плюс найдено: на длинных абзацах (больше 512 токенов) RUAccent падает и программа размечает по отдельным фразам - контекст для омографов теряется.

### Что сделать (всё автоматически, без действий Андрея)

1. **Контекст для RUAccent.** Длинный абзац резать не на голые фразы, а на окна из нескольких предложений до 512 токенов с соседними предложениями как контекстом; знаки брать для центральной части окна.
2. **Омографы и ё - всегда по контексту.** Каждый омограф и каждое «все/всё», «ее/её» и т. п. решать с полным предложением и соседями: RUAccent-омографы + ё-фикатор, а при сомнении (низкая уверенность или расхождение с silero-stress) - локальная модель (`core/homograph_llm.py`) с контекстом. Не только при расхождении двух разметчиков.
3. **Редкие слова (не омографы).** Где RUAccent и silero-stress расходятся на обычном слове («щавель», «красивее») - сверять с большим готовым словарём ударений (открытые словари по Зализняку, Викисловарь и т. п.; проверить лицензию). Это **встроенный справочник программы**, Андрей его не ведёт и не видит.
4. **Предпроход по всей книге до озвучки.** Собрать все уникальные формы слов книги, спорные решить один раз по пп. 2-3, сохранить в служебный кеш книги. Разметка книги не зависит от того, в какой кусок попало слово.
5. **Независимая проверка после синтеза.** Сравнивать звук не с разметкой, а с решением пп. 2-3; при расхождении - пересинтез куска (до 2 раз). Оставшиеся сомнительные места - в журнал книги списком «слово - время в записи», Андрею ничего делать не нужно.
6. **Замер.** Набор 50 слов - 3 прогона подряд (разброс!), цель - не меньше 49 из 50 в каждом. Плюс 300 случайных слов из трёх реальных книг Андрея (из `Книги/`), проверка по meter2 и по словарю Зализняка - доля ошибок до и после. Таблица по шагам 1-5: что дал каждый.
7. Вариант E (ручной словарь) - только как верхняя граница в таблице, в программу не встраивать.

## Д. Шаг 2 - дообучение (после А-Г, последним в очереди)

Цель - не только тембр, но и манера (Герасимов тянет слова), и один голос на всю книгу без смены дикторов. По практике (Baseten, официальный README дообучения Qwen3-TTS): дообучение запекает средний вектор голоса в модель, голос не дрейфует между кусками; манера и выразительность передаются лучше, чем клонированием; данных - от 1,5 часа и больше, чем больше - тем лучше. Подготовить данные (по 1-2 часа чистого чтения каждого), проверить, хватает ли Mac. Если нужна облачная видеокарта - остановиться и написать Андрею цену.
