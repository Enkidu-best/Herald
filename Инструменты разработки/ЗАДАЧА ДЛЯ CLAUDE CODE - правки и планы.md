## A. Мелкие правки интерфейса

### A1. Процент выполнения при записи
Прогресс уже считается: `pipeline` зовёт `progress(fr, msg)`, где `fr` = 0..1.
В `tts_gui.py:721 _progress()` сейчас только двигается полоса и пишется `msg`.
Добавить число процентов. Проще всего в статус-строку:
`self.status.configure(text=f"{int(fr*100)}% — {msg}")`, либо отдельным label
у полосы. Проверить, что на пробнике и на книге показывает 0→100.

### A2. Таймер в часах и минутах
Форматтер уже есть (`tts_gui.py:80`, даёт «1 ч 05 мин»/«3 мин 56 с»). НО живой
таймер (`tts_gui.py:718`) печатает `MM:SS` мимо него:
`self.timer.configure(text=f"{el // 60}:{el % 60:02d}")`.
Заменить на формат Ч:ММ:СС или на существующий форматтер, напр.:
`h=el//3600; m=(el%3600)//60; s=el%60; text = f"{h} ч {m:02d} мин {s:02d} с" if h else f"{m} мин {s:02d} с"`.

### A3. Единый вид названий глав/частей
Проблема: у книги (напр. «Жажда власти [litres]») названия частей приходят
разнородно и в заголовке книги есть служебный тег `[litres]`.
Файл `core/chapters.py`. Добавить нормализацию заголовка и применить в
`_title_for()` (стр. 140) и к заголовку книги:
```
_VENDOR = re.compile(r"\s*\[(litres|литрес|litmir|флибуста|flibusta|hardcase)\]\s*", re.I)
def normalize_title(t: str) -> str:
    t = _VENDOR.sub(" ", t)                 # убрать [litres] и подобные
    t = re.sub(r"\s+", " ", t).strip(" .—-")
    # единый вид «Глава N»: ГЛАВА/глава -> Глава; при желании привести
    # словесные/цифровые формы к одному виду (см. вариант ниже)
    t = re.sub(r"^(ГЛАВА|глава)\b", "Глава", t)
    return t[:70]
```
ВАРИАНТЫ по числам в «Глава …»:
- (проще) оставить слова книги как есть, только чистить теги/регистр/пробелы;
- (единообразнее) привести всё к одному виду — либо «Глава 1, 2, 3…», либо
  словами «Глава первая…». Свести к тому, что доминирует в книге, чтобы вслух
  везёт звучало одинаково. Рекомендую второй вариант с параметром-переключателем.

### A4. Длина файла 60 минут + «один файл без частей»
GUI: `tts_gui.py:72 FILE_LENGTHS` — добавить `"60 минут"` и `"Один файл (без частей)"`.
`file_minutes()`/`_conv_options()` (стр. 687): если выбран «Один файл» —
не резать по времени.
Реализация «один файл» — два способа:
- (просто) выставить `minutes_per_file` очень большим (напр. 100000): тогда
  `build_chapters` вернёт один кусок → один mp3. Годится, наименьшие правки.
- (правильно) добавить в `ConvertOptions` флаг `single_file: bool`. При нём
  синтез идёт по главам (для потоковой выдачи и надёжности), а в конце все
  wav-главы склеиваются в ОДИН файл через ffmpeg concat (как `assemble_m4b`,
  но в mp3/m4b). Плюс: не рвётся книга, не теряется потоковость. Рекомендую этот.
Учесть: один mp3 на 8 ч ~ 660 МБ — нормально; для m4b удобнее (главы-закладки).

## C. Интонация — что реально
Честно: у F5 НЕТ прямого управления эмоцией/интонацией (нет SSML, нет тегов
pitch/emotion). Интонация берётся из двух источников, на них и влияем:
1. **Манера образца.** F5 копирует подачу референса. Более выразительный,
   «читающий с чувством» образец → живее интонация. Можно держать 2-3 образца
   одного диктора (спокойный/напряжённый) и брать под сцену — но это усложняет и
   рискует единообразием тембра.
2. **Пунктуация и темп текста — главный доступный рычаг.** Точка/запятая/тире —
   паузы; «?» — восходящая интонация; «!» — эмфаза; «…» — растянутая пауза.
   Реально сделать:
   - нормализатор пунктуации (чинить кавычки, тире, многоточия, расставлять
     паузы у прямой речи);
   - per-предложение темп/паузы: у «…» пауза длиннее, у «!» чуть медленнее и
     громче, вопрос — не тараторить. В пайплайне уже есть per-chunk `speed_mul`
     (для заголовков) — расширить на эвристики по знакам конца фразы.
   - прямая речь: небольшая пауза до/после реплики, возможно чуть иной темп.
Вывод: заметная, но не «эмоциональная» интонация достижима через пунктуацию +
пейсинг. Настоящее управление эмоциями = другая модель (instruct/emotion-TTS),
а это потеря одобренного голоса — не рекомендую.

## D. Фоновая музыка — реально, это ffmpeg
Добавляется пост-обработкой, к голосу модель не трогаем. Варианты:
1. **Интро/аутро** — музыкальная заставка в начале/конце главы или книги, с
   fade. Классика аудиокниг, ненавязчиво.
2. **Подложка под весь текст** — тихий фон с «дакингом» (ducking): музыка
   автоматически приглушается под речью через sidechain-компрессию. Для книг на
   любителя (может отвлекать), но делается.
ffmpeg-скетч (подложка с дакингом):
```
ffmpeg -i narration.wav -stream_loop -1 -i music.mp3 -filter_complex \
 "[1:a]volume=-22dB[m];[m][0:a]sidechaincompress=threshold=0.03:ratio=8:attack=5:release=300[dm];\
  [0:a][dm]amix=inputs=2:duration=first:dropout_transition=0[out]" \
 -map "[out]" out.mp3
```
Опция в `ConvertOptions`: `music_mode: none|intro_outro|bed`, путь к треку,
громкость, ducking. Музыку пользователь кладёт сам (важно: royalty-free/лицензия).
Интро/аутро проще и безопаснее по восприятию — рекомендую начать с него.

перечитывает файлы на диске. НЕЛЬЗЯ: перезапускать идущую программу и запускать
тестовый синтез/voice_report ОДНОВРЕМЕННО с начиткой — MLX-тест дерётся за
видеоядро, замедлит обе задачи и рискует памятью. Порядок: код править можно
сейчас; тестировать и пушить в GitHub — после завершения текущей книги.
