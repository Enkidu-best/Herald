# Эталонные настройки звука — НЕ МЕНЯТЬ без прослушивания

Зафиксировано 28.09.2026 по прямой просьбе слушателя: «возвращай к наиболее
оптимальной версии». Это состояние коммита `ad40692`, на котором был получен
результат «звука 1 мин 51 с, счёт 2 мин 22 с (1,28 с на секунду звука)» и
отзыв «в остальном всё хорошо».

Любая правка этих чисел проверяется НА СЛУХ человеком. Числовые метрики
(разборчивость по ASR, пик, доля сэмплов у потолка) ловят грубые поломки, но
трижды подряд пропускали то, что слышно сразу: «железный звук», «как из бочки»,
щелчки. Мерить и менять — не одно и то же.

## Звуковой тракт (`core/assemble.py`)

```
HD_FILTER =
    highpass=f=50                             срез инфранизкого гула
    equalizer=f=110:t=q:w=1.0:g=3.5           тело и бас голоса
    equalizer=f=450:t=q:w=1.4:g=-1            чуть убрать «бочку»
    equalizer=f=3500:t=q:w=1.5:g=2            присутствие согласных
    equalizer=f=7500:t=q:w=1.4:g=2            «воздух»
    lowpass=f=11000                           срез вокодерных артефактов
    volume=4dB
    alimiter=limit=0.95
    aresample=48000
```

Формат по умолчанию: mp3 192 кбит/с, `-write_xing 1`.

**Важно про `volume=4dB` + `alimiter`.** Замеры показывают, что эта пара
загоняет сигнал в потолок (пик 0,98, 0,001% сэмплов у максимума) и по числам
выглядит хуже, чем нормализация по пику. Но слушатель сравнил оба варианта и
выбрал ЭТОТ. Вариант с нормализацией по пику (пик 0,85, ноль у потолка) он
описал так: «щелчки ушли, но качество стало значительно хуже и нестабильнее,
опять появился железный звук и звук как из бочки». Не трогать.

## Синтез (`core/engines/f5_mlx.py`)

```
max_chunk_chars   = 280      длина куска текста
MAX_TOTAL_SEC     = 34       образец + речь в одном вызове модели
DURATION_HEADROOM = 1.22     запас времени на кусок
SHORT_CHUNK_CHARS = 80
SHORT_HEADROOM    = 1.30     запас для коротких кусков
steps             = 7        шагов ODE
schedule          = "epss"   прорежённое расписание (Fast F5-TTS)
speed             = 1.0      множитель к темпу, подогнанному под образец
темп образца      clip(0.5, 3.5) — БЕЗ ограничения 1.6
target_bps        ru 29.7, en 16.1
```

## Нарезка и проверки (`core/pipeline.py`)

```
MIN_HEADING_CHARS     = 25    короче — заголовок склеивается с абзацем
MERGE_UNDER_FRACTION  = 0.95  докуда набирать кусок из абзацев
MIN_CHUNK_CHARS       = 45
HEADING_SPEED_MUL     = 0.88  заголовок читается размереннее
gap_sec / para_gap_sec = 0.35 / 0.7
_ASR_MODEL = mlx-community/whisper-small-mlx
проверка краёв: конец — по предфильтру громкости, начало — всегда
TAIL_RETRIES = 2
```

`CHARS_PER_SEC = 12` в `core/chapters.py` — единственное, что оставлено из
поздних правок: это только прогноз длительности, на звук не влияет.

## Что было откачено и почему

| Правка | Почему убрана |
|---|---|
| нормализация громкости по пику (0,88) вместо `volume=4dB` + лимитера | «железный звук и как из бочки», нестабильно |
| затухание 10 мс на обрезке хвоста куска | входило в тот же откат |
| `PACE_LIMIT = 1.6` (ограничение множителя темпа) | входило в тот же откат |
| `MIN_HEADING_CHARS = 45` | входило в тот же откат |
| проверка обоих краёв всегда | входило в тот же откат |

## Известные недостатки этой версии

Слушатель их принял («в остальном всё хорошо»), но они есть:

1. Иногда пропадают окончания слов и первое слово куска.
2. Название главы читается неправильно или пропадает.
3. По числам сигнал прижат к потолку — теоретически это искажения, но на слух
   этот вариант оказался лучше остальных.
