## 1. Ударения — В ПАЙПЛАЙНЕ (`core/stress.py`, вызывается в `pipeline._prepare_text`)
- Нейросеть **RUAccent** (модель omograph `turbo3.1`, `use_dictionary=True`)
  автоматически ставит `+` перед ударной гласной на весь текст.
- Формат `+` понимает модель F5 accent_tune. Пример:
  «много разных тварей» → «мн+ого р+азных тв+арей».
- Применяется, если у движка `stress_format == "+"` (у F5 и Silero — да).

## 2. Темп речи — В ПАЙПЛАЙНЕ (параметр движка F5)
- Сейчас `speed=1.0`, регулируется из окна («Темп чтения»).
- 1.55 стояло раньше и было КОСТЫЛЁМ: образец брался с начала главы, где диктор
  медленно читает заголовок (13,9 байт/с вместо ~29), из-за чего F5 растягивал
  речь вдвое. С нормальным образцом ускорять нечего.

## 3. HD-постобработка ffmpeg — ТОЛЬКО В ДЕМО (в пайплайн НЕ встроено)
Точная строка фильтров (`-af`):
```
highpass=f=80, equalizer=f=350:t=q:w=1.2:g=-2.5, equalizer=f=4000:t=q:w=1.5:g=3, equalizer=f=9000:t=h:w=2000:g=4, loudnorm=I=-16:TP=-1.5:LRA=11, aresample=48000
```
Полная команда, как применялась к клипу:
```
ffmpeg -y -i in.wav \
  -af "highpass=f=80, equalizer=f=350:t=q:w=1.2:g=-2.5, equalizer=f=4000:t=q:w=1.5:g=3, equalizer=f=9000:t=h:w=2000:g=4, loudnorm=I=-16:TP=-1.5:LRA=11, aresample=48000" \
  -codec:a libmp3lame -q:a 2 out.mp3
```
Что делает каждая ступень:
- `highpass=f=80` — срезает гул/рокот ниже 80 Гц.
- `equalizer f=350 g=-2.5` — убирает эффект «бочки/ведра» (избыток нижней середины).
- `equalizer f=4000 g=+3` — присутствие и разборчивость согласных.
- `equalizer f=9000 (high-shelf) g=+4` — «воздух»/яркость.
- `loudnorm I=-16:TP=-1.5:LRA=11` — выравнивание громкости по EBU R128.
- `aresample=48000` — переводит 24→48 кГц (это НЕ добавляет реальных верхов, только формат).

Честный потолок: F5 отдаёт 24 кГц (реальный спектр до ~10-12 кГц). Замер спектра
подтвердил: у клона 99% энергии ниже ~5 кГц, у живого диктора — до ~10 кГц.
Эквалайзер вытягивает воспринимаемую яркость, но настоящие верхние частоты
физически не создаёт.

## 4. Подготовка образца голоса — В ПАЙПЛАЙНЕ (`core/engines/f5.py: prepare_reference`)
Переписано 27.09.2026. Было: первые 10 секунд файла + `faster-whisper small`
(врала: «раздерающимскрежитан» вместо «душераздирающим скрежетом»).
Стало: программа слушает запись в ~24 точках, расшифровывает
`mlx-community/whisper-large-v3-turbo` и выбирает отрывок 8-12 с по критериям
в порядке важности:
1. **чистота фона** (SNR, главное — см. выше);
2. плотность речи около 29 байт/с;
3. громкость около 0,12 RMS.
Границы берутся по границам фраз из расшифровки, а не «ровно 10 секунд».

## 5. Чего НЕ делали, но можно — для НАСТОЯЩЕГО «HD»
- **Нейро-супер-разрешение звука**: `AudioSR`
  (github.com/haoheliu/versatile_audio_super_resolution) или `FlashSR` — достраивают
  верхние частоты (любой звук → 48 кГц с реальным доп. содержанием). Тяжело по
  вычислениям; применять разово к готовому файлу/главе.
- **Онлайн-очистка** образца или выхода: Adobe Podcast Enhance
  (podcast.adobe.com/enhance) — сильно чистит речь, но это облако (разово ок).

## Действие для Claude Code (если нужно поднять качество книги, а не только демо)
1. Встроить HD-цепочку из п.3 в `core/assemble.py → encode_chapter_mp3`
   (сейчас там простой `libmp3lame` без фильтров). Сделать флагом в `ConvertOptions`
   (например `hd_filter: bool = True`), применять `-af "<цепочка>"` при кодировании.
2. Опционально: добавить финальный шаг AudioSR (флаг `upscale: bool`) — прогонять
   готовую главу через супер-разрешение. Учесть стоимость по времени.
3. Пороги EQ (350/4000/9000 Гц) можно подстроить на слух под конкретный голос.
