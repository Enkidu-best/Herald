## 2. Недостающие проверки (добавлены)
`voice_report.py` дополнен: **треск/щелчки в секунду, шероховатость (дребезг),
джиттер** («скрип/фрай»), и режим **`--gate`** — код ошибки, если металл/шип/треск
выше диктора. Гейт заворачивает 10/12/13.

**Организационный вывод (главное).** Claude Code не слышит звук. Значит, он ОБЯЗАН
опираться на метрики и не выпускать образцы, не прошедшие гейт против их диктора.
10/12/13 доходили до слушателя бракованными. Системно:
- `voice_report.py --gate --target <файл ЭТОГО чтеца>` ПЕРЕД показом вариантов;
- не предлагать то, где металл/шип/треск выше оригинала;
- у каждого голоса — свой профиль-цель (Вячеслав ≠ Ященко).

## 3. Что ещё поправить
- **F0 клона на 25-35 Гц ниже оригинала** у обоих чтецов — F5 занижает высоту.
  Крутить темп/длину образца, если нужен «тот самый» голос.
- **Верх упирается в вокодер.** EQ не создаёт верх, только усиливает шум. Реальный
  шаг для Ященко — речевое до-улучшение **Resemble Enhance** (офлайн, естественный
  верх без «металла») или смена вокодера. Для тёмного Вячеслава почти не нужно.
- **Де-эссер** (узкий динамический вырез 6-8 кГц) для №7 и всех «звонких».
- **Отбор образца — по чистому верху, а не по максимуму яркости.**

## 4. Оптимизация: не съедать слова в заголовке и первом предложении
### БЕЗ увеличения времени записи (выходит даже быстрее)
Причина: заголовок — короткий отдельный первый кусок, первый токен F5 нестабилен,
плюс жёсткий срез образца по кадрам. Лечение структурное, без пересинтеза:

1. **Заголовок + первое предложение — ОДИН вызов.** «Глава первая. Ветер с залива.
   К вечеру…» одним куском. Убирает хрупкость и короткого куска, и первого токена.
   Вызовов МЕНЬШЕ → быстрее.
2. **Разгон первого куска главы:** служебное «…»/слово-затравка в начало, срез по
   паузе. Реальное первое слово перестаёт быть нестабильным первым токеном.
   ~0.2 c звука, которые и так срезаются — на время не влияет.
3. **Граница образец→речь по энергии/паузе, а не по фиксированному `ref_frames`.**
   Чинит и съеденное первое слово, и обрубленное окончание («залива»→«зали»).
4. **Убрать дорогой ASR-пересинтез** в пользу 1-3. Сейчас проверка краёв — 17%
   времени. Детерминированные фиксы закрывают ту же проблему. Итог: нейтрально/быстрее.
