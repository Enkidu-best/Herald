# Бриф для Claude Code — проект «Текст в Аудио»

## Что это
Локальное настольное приложение для Mac (Apple Silicon, M4): превращает текст
книги в аудиокнигу голосом-клоном, полностью офлайн и бесплатно. Зеркало проекта
Scribe (там было аудио→текст, тут текст→аудио). Весь код уже в этой папке.

## СОСТОЯНИЕ: ускорение сделано (26.09.2026, замеры на этом M4, 16 ГБ)

Было: torch на CPU, **RTF 5,5** — час звука за 5,5 часа.
Стало: **RTF 0,62** — час звука за 37 минут, **быстрее реального времени**,
тем же голосом. Ускорение **в 9 раз**. Книга `<твоя книга>.fb2` (8,3 ч звука):
было ~46 часов, стало ~5 часов.

Разборчивость (доля слов, распознаваемых обратно; замер на целой главе,
219 слов): **94,1% против 94,5%** у эталонного torch-варианта — разница меньше
одного слова, то есть речь та же.

Ускорение сложилось из двух независимых вещей:

**1. MLX вместо torch (в 4 раза).** Тот же чекпойнт, та же математика: выход
DiT на MLX совпадает с torch с точностью float32 (~1e-4), подготовленный
образец совпадает посэмплово. Пришлось починить три поломки (ниже).

**2. EPSS — прорежённое расписание шагов (ещё вдвое).** Из работы «Accelerating
Flow-Matching-Based TTS via Empirically Pruned Step Sampling» (arXiv 2505.19931,
Fast F5-TTS). У F5 траектория ОДУ почти вся «решается» в начале, поэтому шаги
надо густо ставить у t=0 и прореживать к t=1. Вместо 15 равномерных шагов —
7 неравномерных `[0,2,4,6,8,16,24,32]/32` (дальше обычный sway sampling).
Это НЕ переобучение и не другая модель, только другие моменты времени —
голос тот же. Таблица расписаний в `EPSS_STEPS` (`core/engines/f5_mlx.py`),
переключается `--schedule epss|uniform`.

### Почему MLX раньше давал кашу — три независимые причины
1. **В кэше лежал файл ОТ ДРУГОЙ МОДЕЛИ.** `~/.cache/text2audio/f5mlx_model/model_v1.safetensors`
   копировался «если файла нет», и там остался чекпойнт от прошлых опытов
   (похоже, `ink-splatters/f5-tts-russian-mlx`). Имена слоёв совпадали, поэтому
   он загружался без единой ошибки — но это были не те веса. Теперь стоит
   символьная ссылка, и её цель проверяется при каждой загрузке.
2. **Токенизация ломала кириллицу.** Свой `convert_char_to_pinyin` в f5-tts-mlx
   (устаревший) ставит пробел перед каждым неlatin-символом: «несмотря» ->
   «н е с м о т р я», 41 токен вместо 41 превращался в 74. В torch-версии эта
   ветка закрыта проверкой `is_chinese()`. Перенесён torch-вариант, сверен на
   435 реальных фрагментах — расхождений 0.
3. **Длительность считалась своей эвристикой** (символы/14) вместо формулы F5
   (по БАЙТАМ utf-8 и длине образца) — текст «сжимался» вдвое. Плюс образец
   брался как есть, а torch ВСЕГДА режет в нём тишину (8,9 с вместо 10,0 с) —
   это ещё 12% разницы в темпе.

Проверено численно: выход DiT на MLX совпадает с torch с точностью float32
(расхождение ~1e-4), подготовленный образец совпадает посэмплово.

### Если готовы отказаться от клона голоса
Встроенный в macOS `say -v Milena` — **RTF 0,03** (час звука за 2 минуты).
Готовый голос, не клон, звучит проще; образец в «Сравнение скорости».
Улучшенные русские голоса Apple ставятся вручную: Системные настройки →
Универсальный доступ → Устная речь → Системный голос → Управление голосами.
Из коробки стоит только базовый compact-вариант.

### Что проверено и НЕ помогает на этой машине
- **MPS через torch** — тупик: OOM на 16 ГБ (внутри F5 два куска считаются
  двумя потоками, пик памяти удваивается), а где не падает — RTF 13–18.
- **Квантизация 8/4 бита** — 1,47 против 1,41. Расчёт упирается в арифметику,
  не в память (в отличие от языковых моделей).
- **float16 / bfloat16** — 1,50 / 1,52 против 1,40. На M4 fp32-матумножение и так
  идёт на полной скорости.
- **`--workers 2`** — 376 с против 372 с: видеоядро занято и одним процессом.
- **Куски длиннее 200 символов** — быстрее на 6%, но разборчивость падает до 89,9%.
- **Округление длины куска** под `mx.compile` — перекомпиляция стоит 0,03 с на
  кусок, экономить нечего.

Упор в железо: шаг ОДУ 862 мс ≈ 2,4 TFLOPS ≈ 56% от пика fp32 M4. 99,5% времени
в DiT. Дальше без потери качества эта модель на этом чипе не ускорится.

### Попутно исправлено
- **`Fatal Python error: config_init_hash_seed`** в torch-движке. `F5TTS.infer`
  без явного seed берёт `random.randint(0, sys.maxsize)` и кладёт это в
  `PYTHONHASHSEED`, где допустимо только 0..4294967295. После этого падал любой
  дочерний python (вспомогательный процесс multiprocessing) и в консоль летела
  ошибка. Теперь seed задаём сами в допустимом диапазоне.

### Что осталось на выбор пользователя
- Какой режим оставить (образцы в «Сравнение скорости», `compare_speed.py`).
  По умолчанию epss-7. Есть epss-6 (RTF 0,51) и uniform-16 (RTF 1,27, эталон).
- Расшифровка образца сделана whisper-small и **неверна**:
  «раздерающимскрежитан» — это одно слово-мусор. F5 сверяет образец с его
  текстом, так что более точная расшифровка (whisper medium/large) скорее всего
  улучшит голос и уберёт нужду в `speed=1.55`. Но это ИЗМЕНИТ звучание, а голос
  одобрен как есть — поэтому не трогал.
- Более короткий образец (6 с вместо 8,9 с) дал бы ~1,17x: образец
  пересчитывается на каждом куске. Тоже меняет клон, поэтому не трогал.

## АУДИТ 27.09.2026 — что нашлось и что исправлено

### Исправлено
1. **Разбивка на главы искала слово «Глава».** У книг глав может не быть, а два
   заголовка подряд давали файл на 2,5 секунды из одного названия. Теперь
   `chapters.py` режет по РАЗМЕРУ (длина задаётся в минутах звука), а заголовки
   — только предпочтительные места разреза и источник имён файлов.
2. **Пробник выдавал 0,2 с тишины.** Брал главу «посередине по счёту», а ею
   оказывался пустой заголовок. Теперь берёт самый длинный кусок.
3. **Образец голоса брался с начала записи**, где диктор медленно читает
   заголовок: 13,9 байт текста на секунду вместо обычных ~30. F5 считает
   длительность по этому соотношению, поэтому растягивал речь вдвое — что
   компенсировали темпом 1.55, отчего голос беднел. Теперь `prepare_reference`
   слушает запись в 7 точках, выбирает отрывок с самой плотной речью и режет
   строго по границам фраз. Темп вернулся к 1.0: на выходе 29,6 байт/с против
   30,9 у живого диктора.
4. **Расшифровка образца делалась моделью `small` и врала**
   («раздерающимскрежитан» вместо «душераздирающим скрежетом»). Неверный текст
   образца портит клон. Теперь Whisper large-v3-turbo на MLX — секунды на
   отрывок вместо 8 минут у large-v3 на CPU.
5. **Числа читались неправильно:** «5-е» → «пять-е», «в 1990 году» → «одна
   тысяча девятьсот девяносто году», «1%» → «один процентов», римские цифры
   оставались латиницей («Глава XIV»). Всё исправлено в `normalize.py`
   (порядковые, годы, проценты, римские) — см. там же тесты в примерах.
6. **Не было пауз между абзацами.** Вся глава резалась одной лентой с паузой
   0,35 с везде, поэтому заголовок сливался с первым абзацем. Теперь
   `_chunk_paragraphs` даёт длинную паузу на границе абзаца.
7. **Окно молча падало на старте:** свой метод `_options()` перекрывал
   `tkinter.Misc._options`. Переименован в `_conv_options`.

### Найдено, но осознанно оставлено
- `_hard_split` может разорвать слово, если предложение длиннее 200 символов и
  в нём нет ни запятых, ни тире. На реальных книгах почти не встречается.
- `--workers` в CLI для MLX бесполезен (видеоядро занято одним процессом), но
  флаг оставлен: он осмыслен для torch-движка.
- Silero-движок работает, но из окна убран — его голос заметно хуже двух других.
- `.m4b` собирается только из CLI (`--m4b`); в окне галку убрали, потому что
  слушать по файлам удобнее, а сборка одного файла на 8 часов долгая.

## Интерфейс (переделан)
- Запуск — двойной щелчок по `Запустить.command`.
- Книга добавляется перетаскиванием в окно (tkinterdnd2 + customtkinter:
  класс окна наследует и `ctk.CTk`, и `TkinterDnD.DnDWrapper`).
- Перед стартом показывается оценка: глав / часов звука / часов расчёта
  (`estimate_book()` в pipeline — читает и считает символы, без синтеза).
- Есть «Стоп» (`should_stop` в `convert_book`, исключение `Cancelled`).

  окно на старте с TypeError в `configure`. Поэтому `_conv_options`.

## Архитектура
```
core/
  readers.py     форматы -> Document (текст, метаданные, обложка)
  normalize.py   числа/сокращения -> слова, чистка
  stress.py      RUAccent, ударения «+»
  chapters.py    разбивка на главы
  engines/
    base.py      интерфейс TTSEngine (sample_rate, max_chunk_chars, stress_format, synth_chunk)
    f5.py        F5 torch (основной рабочий), device cpu/mps
    f5_mlx.py    F5 на MLX (быстрый, пока каша — чинить)

```

## Как запускать / замерять
Пользователю: двойной щелчок по **`Запустить.command`**.

```
source .venv/bin/activate
# вся книга (движок f5mlx и epss-7 — по умолчанию, флаги не нужны):
python cli.py "Пример — проба пера.txt" --voice "голос диктора"
# пробник ~1 мин из середины (глава 2: в тестовом файле 1 и 3 — пустые заголовки):
python cli.py "Пример — проба пера.txt" --voice "голос диктора" --preview 1 --chapter 2
# эталон для сверки (равномерные 16 шагов):
python cli.py "Пример — проба пера.txt" --voice "голос диктора" --preview 1 --chapter 2 \
    --schedule uniform --nfe 16
# torch-эталон (медленно, для численной сверки):
python cli.py "Пример — проба пера.txt" --engine f5 --voice "голос диктора" --preview 1 --chapter 2
# замер + проверка разборчивости:
python bench.py --engine f5mlx --out bench_out/x.wav && python verify.py bench_out/x.wav
# сравнить режимы на слух:
python compare_speed.py
```
CLI печатает `Длительность`, `громкость(RMS)` и `счёт ... c` — по ним считать RTF
(счёт / длительность). Сейчас 0,62.

ВАЖНО про замеры: разборчивость от `verify.py` на 3 куска́х (57 слов) шумит на
±3% — одно слово решает. Выводы делать на целой главе (219 слов), иначе легко
«увидеть» разницу там, где её нет.

## Критерий готовности — выполнен
Быстрее реального времени (RTF 0,62) тем же голосом-клоном и с верными
ударениями; mp3 по главам выдаются по порядку и слушаются на ходу.
Глава на 20-30 мин звука считается 12-19 минут.
